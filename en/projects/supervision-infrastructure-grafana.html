Infrastructure monitoring with Grafana

Deploying a complete observability stack for system metrics, business data, logs and alerts on containerised infrastructure.

TypeMaster’s-level lab — Security Monitoring module
EnvironmentTeaching lab (2 VMs)
Deliverable58-page report
StatusCompleted

Context

Setting up observability on containerised infrastructure in a teaching environment simulating isolated research bases (TAAF). The architecture uses two virtual machines on an internal network: one for application services and one for monitoring.

Objectives

  • Deploy a complete observability stack using containers.
  • Design Grafana dashboards for containers and business data.
  • Write relevant PromQL and SQL queries.
  • Set up alerting and log analysis.

Architecture and operation

Prometheus collects system and container metrics through cAdvisor, node_exporter and postgres_exporter. Grafana centralises visualisation, while Loki aggregates logs collected by Grafana Alloy. Dashboards combine technical metrics from Prometheus with business data from PostgreSQL.

Work completed

  • Infrastructure validation: connectivity between VMs, firewall, Docker network and service availability.
  • Container monitoring with cAdvisor and Prometheus: status, resource usage and disk I/O.
  • Business dashboards querying PostgreSQL with SQL.
  • Loki and Alloy integration for logs, with alerting rules.

Results

Working monitoring dashboards for containers and business data, alerting and centralised logs. The process, queries and interpretations were documented in a 58-page lab report.

Skills demonstrated

End-to-end observability (metrics, logs, dashboards and alerts), Docker Compose containerisation, PromQL/LogQL/SQL queries and network troubleshooting: foundations relevant to SOC work.

Technologies

  • Docker Compose
  • Prometheus
  • Grafana
  • Loki
  • Grafana Alloy
  • cAdvisor
  • PostgreSQL
  • PromQL
  • LogQL
