AI gesture recognition (webcam)

Recognising rock, paper and scissors gestures from webcam images, then playing a real-time game against the computer. Two neural networks were compared; the best reaches 94.6% accuracy.

TypeArtificial intelligence course project (4th year)
TeamTwo students
LanguagePython · PyTorch
Deliverable40-page report and live demo

Context

This ESIROI artificial intelligence project covers the whole computer vision workflow: preparing images, training and comparing models, then using them in an interactive application. The user makes a gesture in front of the webcam, the system recognises it and plays a round against them.

Objectives

  • Prepare and explore a dataset of hand images in three classes: rock, paper, scissors.
  • Compare a network designed for the task with a pre-trained network.
  • Evaluate the models on images they have never seen.
  • Integrate recognition into a game that runs in real time.

Data

The dataset is the Rock Paper Scissors set published by TensorFlow, with a training set and a separate test set. The three classes are balanced. Images are resized to 128 × 128 pixels and normalised.

Many images have plain backgrounds and even lighting, much simpler than a real webcam. To narrow that gap, every training image goes through random transformations: flips, rotations up to 20°, colour and brightness changes, shifts and zoom, conversion to greyscale, and masking of a region.

Two models compared

  • Network designed for the task : four convolution blocks (32 to 256 filters) with normalisation and dropout, followed by a three-output classifier. About 1.2 million parameters, trained from scratch.
  • Pre-trained MobileNetV2 : a lightweight network already trained on ImageNet, with its last layer replaced. Training happens in two steps: first the new layer alone, then the last five blocks with a very small learning rate.

Both models follow the same protocol: 90% of the training images for learning, 10% for validation, the test set kept for the final evaluation, a fixed random seed, learning-rate reduction and early stopping when validation stops improving.

Results

The network designed for the task achieves the best accuracy, about 94.6% on the test set, ahead of MobileNetV2. On images this simple and this specific, a smaller model trained directly on the data did better than the pre-trained one. The best model is selected automatically and saved with its class mapping, so it can be reloaded without retraining.

Real-time demo

  • Hand detection : MediaPipe Hands locates the hand in the webcam image and finds the finger joints.
  • Reading the gesture : the position of the joints shows which fingers are open or closed.
  • Stabilisation : predictions from the last few frames are kept and the most frequent one is used, so the result does not flicker from frame to frame.
  • Game : an interface with a start screen shows the detected gesture, the computer's move, the score and the result of each round.
  • Single image : a function also analyses one image and displays the model's confidence for each class, which helps when studying errors.

Limitations and next steps

  • Errors mostly appear when lighting is poor, the hand is partly out of frame, the gesture is badly formed or the background is cluttered.
  • The dataset lacks diversity: few different hands, angles and lighting conditions.
  • The system only knows three gestures: adding more requires new data and retraining.
  • Next steps: a more varied dataset, systematic hand detection before classification, and a lighter model for low-powered machines.

What I learned

A pre-trained model is not better by default: it has to be compared with a simpler solution, using the same protocol, before choosing it.

A good test score is not enough either: with a real webcam, lighting and background matter as much as the model.
