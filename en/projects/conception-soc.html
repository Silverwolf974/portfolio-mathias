Designing a SOC

Designing a complete Security Operations Center architecture for an IT infrastructure: log collection, detection, correlation, visualisation and response procedures.

TypeAcademic project — first year of Master’s-level study
TeamGroup
Period2025 – 2026
Deliverables3 stages (analysis, benchmarking, architecture)

Context

The infrastructure under study (Proxmox hypervisor, SSH and HTTP bastion hosts, Gitea, internal DNS and an OPNsense firewall) lacked centralised security monitoring. The project involved designing a SOC suited to this environment: selecting log sources, choosing analysis tools and prioritising threats to detect.

Objectives

  • Assess infrastructure risks and prioritise threats.
  • Benchmark SIEM and IDS solutions and justify the chosen stack.
  • Design a layered architecture for collection, detection, correlation, visualisation and response.
  • Define actionable detection use cases mapped to MITRE ATT&CK.

Selected architecture

A layered architecture built around an open-source stack: Wazuh as an all-in-one SIEM (integrated Elasticsearch and Kibana, with native MITRE ATT&CK mapping), Suricata as the IDS/IPS, Prometheus + Grafana for infrastructure monitoring, and multi-source collection through Wazuh agents, Syslog (RFC 5424) and Filebeat. Alerting combines native Wazuh notifications, email and a scripted Discord webhook.

  • Sources covered : SSH/HTTP bastion hosts, Gitea, internal DNS (Bind9), OPNsense firewall and Proxmox hypervisor.
  • Detection : eight priority use cases covering 17 MITRE ATT&CK techniques, including SSH brute force, lateral movement and exfiltration.
  • Response : triaged alerts and documented manual procedures (SOAR was outside the scope).

Work completed

  • Stage 1 — assessment of the existing infrastructure and its risks.
  • Stage 2 — comparative benchmark of SIEM, IDS and monitoring solutions (LaTeX report).
  • Stage 3 — detailed architecture: SOC overview diagram, inventory of log sources, collection methods per host and eight detection use cases, including severity, MITRE technique, data sources and detection logic.
  • Environment mock-up: deployment of a virtualised OPNsense instance using Docker Compose (KVM).
  • Oral presentation of each deliverable to an assessment panel.

Skills demonstrated

A complete security architecture process: risk assessment, tool selection supported by benchmarking, realistic log collection design and detection logic usable by analysts. This work provided a foundation for my SOC Analyst internship.

Technologies
