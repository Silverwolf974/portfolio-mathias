Detection & evasion of an IDS (Suricata)

Set up the Suricata IDS, check that it detects simple attacks, then build a DNS exfiltration tunnel and make it undetectable — to measure the limits of signature-based detection.

TypeCybersecurity lab project (4th year)
TeamTwo students
PeriodNovember 2025
ApproachRed & blue (attack / detection)

Context

Two virtual machines on an isolated network: a compromised machine that exfiltrates data, and a remote server (C2) that hosts a DNS server and receives the data. The whole analysis relies only on the logs produced by Suricata, without Wireshark, to take the position of an analyst who only has their logs.

Objectives

  • Install and configure Suricata as an IDS on the target machine.
  • Write detection rules for a DNS exfiltration channel.
  • Build a DNS exfiltration tunnel, first naive then stealthy.
  • Understand how an attacker bypasses signature-based rules.

Setup

  • Suricata installed in af-packet mode, with logs in JSON format (eve.json) and the internal network declared as trusted.
  • Custom rules targeting the C2 domain and the abnormally long, purely hexadecimal DNS queries typical of a tunnel.
  • Authoritative Bind9 DNS server on the C2, which accepts any subdomain and logs every query received, so the exfiltrated data can be reassembled.

Detection confirmed

  • A file inclusion (LFI) web attack is correctly detected by Suricata's standard rules.
  • A first "naive" DNS tunnel (data hex-encoded in subdomains) triggers the custom rules: the C2 domain and the length of the labels give the exfiltration away.

Evasion

  • On the web side : simple changes to how the request is written (URL encoding) keep the attack while slipping past the signatures.
  • On the DNS side : a stealthy version of the tunnel replaces hex with Base32, adds a random prefix to each label and spaces out the queries randomly. The traffic then looks like ordinary DNS.
  • Result: no alert fires any more, while the file is exfiltrated and reassembled identically on the C2 side.

Takeaway

The project ends with a clear matrix: a simple web attack is detected, an obfuscated web attack is not detected ; a naive DNS tunnel is detected, a stealthy DNS tunnel is not detected. As soon as the attacker knows the rules, small transformations are enough to neutralise a purely signature-based IDS; DNS is an exfiltration channel that is particularly resistant to static filters.

Next steps

  • Complement signatures with behavioural models (DNS anomalies, statistical analysis).
  • Correlate several sources at a SIEM level and use dynamic thresholds.
  • Consider machine learning on DNS traffic.

What I learned

A detection rule is only worth something as long as the attacker doesn't know it. Writing both the attack and the defence showed me why modern detection combines signatures, behaviour and correlation rather than relying on a single mechanism.

Technologies
