Finding names in text

Does a model that finds people, companies and products reliably in Wikipedia still find them in tweets? We measured the drop, then looked for where it came from.

TypeText mining project (exchange semester, 5th year)
SchoolINSA Lyon
TeamTeam of 3
Deliverables27-page paper and two presentations

Context

The assigned topic was to recognise people, companies and products in text, starting from a published research project: Linked-DocRED (SIGIR 2023). It is built on about 5,000 Wikipedia documents and chains four modules: name detection, grouping mentions of the same entity, relations between entities, and linking to Wikidata.

After the first session, our supervisor asked us to focus on name recognition. The question became: does a model trained on well-written articles stay reliable on short, informal messages?

My role

  • Getting the original code running : the published code did not run as released. I set up one isolated environment per module (three Python versions under WSL2) and fixed the blocking bugs: a hidden 10-document limit, a test that actually used the validation data, a call to the wrong API, and unpinned dependencies. I also adapted training to fit on an 8 GB GPU.
  • Checking the metrics : the published evaluation script only scored the last document and gave a perfect score to nonsensical predictions. I wrote a corrected version.
  • Research : review of the papers citing the original work and a selection grid for datasets.
  • Final experiments : ran all the end-of-project GPU experiments on Google Colab (a model over three random seeds, a test on an additional corpus, preprocessing variants).
  • Communication : mid-term presentation in English and writing the reproduction section of the paper.

Model design and most of the error analysis were led by a teammate.

Approach

Four datasets with different labels were mapped to a common scheme: person, company, product, other. Four families of models were compared: a classic CRF, RoBERTa trained on our data, GLiNER used without training, and a large language model (Llama) prompted with a few examples. All are scored on the same sentences with the same metric, and the test set is only used at the end.

Results

  • For company names, the recognition score drops from 0.68 on Wikipedia to 0.07 on tweets.
  • The best model trained only on Wikipedia-style text drops from 0.835 to 0.375 on tweets. When also trained on tweets, it reaches 0.73.
  • Twitter-specific markup explains about a third of the drop: removing it gains 0.16 for a model that has never seen tweets, but costs 0.05 for a model that has learned them.
  • On review, 26 to 44% of the model’s “errors” were judged correct by two reviewers: part of the drop comes from ambiguous annotations, not from the model.

Limitations

  • The original pipeline was not fully retrained, so the comparison with the published scores is only indicative.
  • Detecting links between entities was taken out of scope at the supervisor’s request.
  • Most results rely on a single random seed; only the largest model was tested on three.

What I learned

I learned to read through examples before drawing conclusions: some errors came from the model, others from ambiguity in the expected answers.

I also learned to test a metric with predictions whose correct score is already known, before trusting it.
